# Xray in Củ Chi

Register a dedicated Ubuntu VPS with the existing SSH form, then choose **Развернуть Xray** on its server card. Open TCP/443 at the provider. The worker installs Docker if required and runs the official Xray-core 26.11.9 image pinned by digest. A clean server can run Xray alone. Each server uses its own X25519 key pair and short ID. During initial deployment the worker tests candidate TLS destinations from the VPS for certificate validity, TLS 1.3 and ALPN h2. It saves a domain after a real VLESS/Vision + REALITY connection carries an HTTPS request. Subsequent reconciliations reuse the saved domain. Release validation runs this installer on a disposable Ubuntu CI runner.

In **Устройства**, issue Xray for a device, wait for the server to confirm application, then select **Подключить Xray**. Import the subscription URL or its QR in a VLESS/REALITY client such as Hiddify. Individual VLESS links are also available. Each enrolled device gets a distinct credential per server. Adding another Xray node automatically provisions existing enrolled devices. Refresh the subscription in the client to fetch its updated list. Hiding a server removes it from refreshed lists. Revoking device access immediately invalidates its subscription and queues server-side removal. An unavailable server keeps revocation pending until it confirms removal. Device deletion waits for this confirmation.

NAS migration 015 is additive. The API uses Synology roles, ownership checks and CSRF. SSH credentials and pins use the existing server inventory. The database/master-key backup covers Xray identities and device subscriptions. Subscription URLs and QR codes grant access: keep them private, including reverse-proxy access logs. The Xray container exits directly via the VPS. AWG/WARP, default-server reminders, Keenetic uplinks and AWG statistics retain their own settings. The server card shows the last application result. A deployment probe proves VPS-side forwarding; reachability from a particular ISP needs a connection from that network.

Applying an updated device list briefly restarts Xray connections on that VPS. A failed candidate is removed and the worker attempts to restore the previous runtime. The worker retries failed deployment after three minutes. To roll back the NAS binary, first revoke Xray grants you intend to remove and verify all servers have applied them. An older NAS version cannot manage deployed Xray containers.
